Aliases are designed for one thing: **turning off unwanted mail instantly**.

## Option A (fastest): disable the alias

::steps
### Open the alias
Open the mailbox, then click the alias that’s getting spam.

### Toggle it to Disabled
Turn **Enabled** off.

From that moment on, new mail to that alias is dropped.
::

::alert{type="warning" title="Disabling blocks everything" icon="lucide:triangle-alert"}
Disabling an alias also blocks legitimate mail (password resets, receipts, security alerts) sent to that address.
::

## Option B: keep the alias but tighten protection

If you still need the alias to work (but want stricter filtering):

- keep the alias **enabled**
- enable **Quarantine and safety checks**
- switch to **Active protection** (so unknown senders are quarantined by default)

## Option C: rotate the address (recommended for important services)

1. Create a new alias for the service.
2. Update the email address in the service’s account settings.
3. After you confirm the new address works, disable the old alias.

For help with vendor changes, see [Vendor migrations](/guides/vendor-migrations).
